# 台账补录 + 日报（51job 版）

与双通道版本同一设计：**台账是唯一事实源，日报从台账同步，不另立事实源**。
51job 特有差异（姓名打码、来源入口命名、`resumeId` 主键）在下文标注。

## 台账 `02-sourcing/dedup-ledger.csv`（唯一事实源）

去重键 = **`resumeId`（主）**。没有 `resumeId` 时才退回**复合指纹**（姓氏+年龄+现职组织+薪资带）。
**禁止**只用「打码名 + 应聘岗位」去重——`张**` 同岗会误合并。

补录前先按 `resumeId` 搜；没有 ID 再扫指纹。命中已有行 → **更新那行**（别新建重复行）；
命中且状态已推进（如「已打招呼」→「已约谈」）→ 别降级、别重复计入，最多在备注记「今日重发/重触达」。

列（表头就是这几列，顺序固定）：

```
序号,resumeId,姓名,应聘岗位,现职/背景,评级,状态,来源入口,简历路径,备注
```

- **序号**：接最后一行 +1（末号可能不连续，取更大值起）。
- **resumeId**：51job 候选人持久键。从 `search --json` 的 `.hits[].resumeId`、`inspect`/`talent-detail --json` 的 `resumeId` 写入。
  有 ID 后回访一律 `inspect --resume-id` / `talent-detail --resume-id`，不要按姓名重搜。空着只允许「尚未打开详情」的列表阶段，打开详情后必须补。
- **姓名**：51job 搜索是打码名（`张**`）。推荐池（recommend）不打码。日报里搜索池名字**保持打码**。
- **应聘岗位**：用 CONTEXT「在招岗位」表里的岗位名，与既有行一致，别造同义词。
- **评级**：⭐~⭐⭐⭐（命脉强 = ⭐⭐⭐）。
- **状态**：`待初筛 / 初筛通过 / 初筛不合适 / 观望 / 已打招呼 / 已回复 / 待确认 / 已约谈 / 面试中 / 已拒 / 已排除`。
  打了招呼 = `已打招呼`；仅记录待用户确认 = `待确认`；命中硬规则 = `已排除`（记原因，**不自动点平台「不合适」**）。
- **来源入口**：`YYYYMMDD` + 渠道入口，如 `20260826推荐 / 20260826搜索 / 20260826未读 / 20260826投递`。
- **简历路径**：下了简历才填（51job 截图/OCR 落盘 `~/.51job-cli/ocr/`；可拷贝到 `runtime/resumes/`
  填相对路径）；没下留空。OCR 默认关闭，需 `51JOB_RESUME_OCR=1`。
- **备注**：技能摘要 + 关键判断。无 `resumeId` 时必须写复合指纹（如 `指纹=黄28岁/8年/1-1.1万/江门市国土测绘大队`），有 ID 后指纹可留作人工核对。

批量补录留意：Windows 控制台默认编码会崩中文/emoji，Python 先
`sys.stdout.reconfigure(encoding="utf-8")`；临时文件用绝对路径。补录后核验：无重复序号、有 `resumeId` 的不重复、按岗位计数对得上。

旧台账若没有 `resumeId` 列：在「姓名」前插入该列，把备注里的 `rid=` 迁过去；迁不了的先留空，下次 `inspect`/`talent-detail` 补。

## 人才简历详情台账 `02-sourcing/人才简历详情台账.csv`（2026-08-31 固化）

dedup-ledger 是**摘要指纹**（状态/评级/一句话），本表是**简历肉质**（多段工作经历原文、教育、技能、求职意向、直链）。
两者用 `resumeId` 关联，主键一致。**每轮凡新 inspect 的候选人都补录**（新增或同 rid 更新），与 dedup-ledger 同轮完成。

**固定列**（顺序固定）：

```
日期,resumeId,姓名,应聘岗位,求职意向,基本画像,技能标签,工作经历,教育背景,简历URL,来源入口,备注
```

- **日期**：`yyyy-MM-dd` = 获取详情当天；同一 `resumeId` 再次获取 → **更新原行**（日期改为本轮），不新增重复行。
- **resumeId / 姓名 / 应聘岗位**：同 dedup-ledger 口径（应聘岗位用 CONTEXT 表内岗位名）。
- **求职意向**：`intention` 原文（如实保留初始意向，不因推荐岗改写）。
- **基本画像**：`年龄岁 / X年 / 学历 / 现居地 / 活跃度`（从 status 提取）。
- **技能标签**：skills 数组顿号连接。
- **工作经历**：多段用 ` || ` 分条，段内 `公司|时段|职责原文`（职责保留完整描述，截断 600 字防爆列）；
  段内文本的 `|`/`;` 转义（`|`→`／`、`;`→`；`）防破列。
- **教育背景**：多段 `学校 | 学历 | 专业 | 时段`，` || ` 分条。
- **简历URL**：只保留 `.../detail?xxxresumeId=<ID>` 核心直链段（去易变的 `requestId` 及其后参数），下次能直接打开。
- **来源入口**：`YYYYMMDD + 渠道`（如 `20260831推荐`）。
- **备注**：初筛关键判断 / 指纹（无 resumeId 时必填指纹）。

**生成方式（首选脚本，防手写错列）**：

```bash
python skills/recruit-daily-51job/scripts/build-resume-detail-ledger.py <JSON目录> \
  --date $(date +%F) --source 20260831推荐 --job 销售主管
```

脚本自动：按 resumeId 去重（重复 JSON 取最后一份）、已有文件 upsert（同 rid 更新）、utf-8-sig 带 BOM（Excel 可开）。
脚本本体是复用的权威实现，本表描述与之同步，改列先改脚本再改本文档。

## 日报（从台账同步，不另立事实源）

**载体二选一，结构相同：**
- 有 `lark-cli` 且已配置 → 飞书云文档：把内容写成文件落在 cwd 相对路径，
  `lark-cli docs +create --content @<相对路径> --as user`（`@file` 只认 cwd 相对路径；
  超长内容走文件）。建完把文档 URL 回给用户。
- 没有 → 本地 `runtime/reports/YYYY-MM-DD.md`，写完把路径回给用户。

**结构建议（非死模板）：**

1. 一句话总结（今天干了什么、最重要的 1-2 个人选）
2. 今日概况：未读处理数 / 寻源覆盖岗位 / 打招呼数 / 台账新增与更新数
3. 岗位优先级（从 CONTEXT 同步，提醒老板当前主攻方向）
4. **按岗人选表**：姓名 ｜ 年龄/学历 ｜ 背景技能 ｜ 评级 ｜ 来源（命脉信号加粗）
5. 渠道观察（今天 recommend / search 哪边池子肥、额度情况、异常）
6. 待办与待确认（等用户拍板的排除名单、待授权的打招呼、CONTEXT 待定决策清单）

**对外红线**：CONTEXT 标注的商业敏感信息不进日报；平台打码名在日报里**保持打码**
（别因台账有真名就放开）；候选人联系方式不进日报正文（留在台账/简历文件里）。

## 关键词迭代闭环（每轮寻源后）

从本轮「初筛通过/强匹配」的真实简历反向提取有效搜索词回填 `CONTEXT.md` 的关键词迭代表：
有效词 / 无效词 / 积极信号 / 拒绝模式。下一轮寻源**先读这张表**。搜索质量依赖词表——
这是整套流程里唯一会“越来越准”的地方。
