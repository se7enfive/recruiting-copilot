# 台账补录 + 日报（51job 版）

与双通道版本同一设计：**台账是唯一事实源，日报从台账同步，不另立事实源**。
51job 特有差异（姓名打码、来源入口命名、简历路径来自 OCR）在下文标注。

## 台账 `02-sourcing/dedup-ledger.csv`（唯一事实源）

去重键 = **姓名 + 应聘岗位**。补录前先搜今天的人名，命中已有行 → **更新那行**（别新建重复行）；
命中且状态已推进（如「已打招呼」→「已约谈」）→ 别降级、别重复计入，最多在备注记「今日重发/重触达」。

列（表头就是这几列，顺序固定）：

```
序号,姓名,应聘岗位,现职/背景,评级,状态,来源入口,简历路径,备注
```

- **序号**：接最后一行 +1（末号可能不连续，取更大值起）。
- **姓名**：51job 搜索是打码名（`张**`）。同岗多个同姓打码名加后缀区分（`张**(测绘)`）。
  推荐池（recommend）不打码，名称直接在页面可见——但**日报里仍保持打码**。
- **应聘岗位**：用 CONTEXT「在招岗位」表里的岗位名，与既有行一致，别造同义词。
- **评级**：⭐~⭐⭐⭐（命脉强 = ⭐⭐⭐）。
- **状态**：`待初筛 / 初筛通过 / 初筛不合适 / 观望 / 已打招呼 / 已回复 / 待确认 / 已约谈 / 面试中 / 已拒 / 已排除`。
  打了招呼 = `已打招呼`；仅记录待用户确认 = `待确认`；命中硬规则 = `已排除`（记原因，**不自动点平台「不合适」**）。
- **来源入口**：`YYYYMMDD` + 渠道入口，如 `20260826推荐 / 20260826搜索 / 20260826未读 / 20260826投递`。
- **简历路径**：下了简历才填（51job OCR 落盘 `~/.51job-cli/ocr/`；可拷贝到 `runtime/resumes/`
  填相对路径）；没下留空。
- **备注**：技能摘要 + 关键判断 + **51job 特有：记 `rid=<详情页 resumeId>`**（从 `51job inspect --json`
  返回的 `resumeId` 字段拿），后续查简历 / 打招呼复用。

批量补录留意：Windows 控制台默认编码会崩中文/emoji，Python 先
`sys.stdout.reconfigure(encoding="utf-8")`；临时文件用绝对路径。补录后核验：无重复序号、按岗位计数对得上。

## 日报（从台账同步，不另立事实源）

**载体二选一，结构相同：**
- 有 `lark-cli` 且已配置 → 飞书云文档：把内容写成文件落在 cwd 相对路径，
  `lark-cli docs +create --content @<相对路径> --as user`（`@file` 只认 cwd 相对路径；
  超长内容走文件）。建完把文档 URL 回给用户。
- 没有 → 本地 `runtime/reports/YYYY-MM-DD.md`，写完把路径回给用户。

**结构建议（非死模板）：**

1. 一句话总结（今天干了什么、最重要的 1-2 个人选）
2. 今日概况：未读处理数 / 寻源覆盖岗位 / 打招呼数 / 台账新增与更新数
3. 岗位优先级（从 CONTEXT 同步，提醒老板当前主攻方向）
4. **按岗人选表**：姓名 ｜ 年龄/学历 ｜ 背景技能 ｜ 评级 ｜ 来源（命脉信号加粗）
5. 渠道观察（今天 recommend / search 哪边池子肥、额度情况、异常）
6. 待办与待确认（等用户拍板的排除名单、待授权的打招呼、CONTEXT 待定决策清单）

**对外红线**：CONTEXT 标注的商业敏感信息不进日报；平台打码名在日报里**保持打码**
（别因台账有真名就放开）；候选人联系方式不进日报正文（留在台账/简历文件里）。

## 关键词迭代闭环（每轮寻源后）

从本轮「初筛通过/强匹配」的真实简历反向提取有效搜索词回填 `CONTEXT.md` 的关键词迭代表：
有效词 / 无效词 / 积极信号 / 拒绝模式。下一轮寻源**先读这张表**。搜索质量依赖词表——
这是整套流程里唯一会“越来越准”的地方。
